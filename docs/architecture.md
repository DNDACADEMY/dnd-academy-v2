# DND 웹 아키텍처

## 애플리케이션 경계

| 경로                                                                                                         | 책임                                                                                             |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `apps/web/src/app`                                                                                           | Next.js App Router. 공개 페이지, 관리자 화면, 수정 링크, 합격 조회 API와 큐 소비자               |
| `apps/web/src/lib/apis`                                                                                      | 공개 페이지의 조회 인터페이스. CMS 활성화 여부에 따라 DB 게시본 또는 저장소의 초기 콘텐츠를 읽음 |
| `apps/web/src/lib/cms`                                                                                       | 입력 계약, 권한, Supabase 접근, 공개 화면 데이터 변환, 미디어와 제출 게시 처리                   |
| `packages/core`, `packages/ui`                                                                               | 공유 도메인 타입·유틸리티와 UI 컴포넌트                                                          |
| `supabase/migrations`, `supabase/tests`                                                                      | PostgreSQL 스키마, RPC, SQL 회귀 검사                                                            |
| [`dnd-frontend/services/passboard`](https://github.com/DNDACADEMY/dnd-frontend/tree/main/services/passboard) | 별도 배포되는 합격 조회 화면. 아래의 웹 API 계약을 사용                                          |

`apps/web` 하나가 공개 사이트와 `/admin`을 제공한다. 조직 Vercel의 `dnd-academy-v2-web`에서 배포하며 함수 리전은 [배포 설정](../apps/web/vercel.json)의 `icn1`이다. Next 서버는 Supabase Auth와 PostgREST를 HTTPS로 호출한다. 애플리케이션에 직접 연결하는 PostgreSQL 드라이버나 앱 수준 DB 커넥션 풀 설정은 없다.

## 공개 콘텐츠와 관리자

- 공개 페이지는 게시된 판본을 읽는다. 홈 프로젝트 카드, 운영진 디렉터리, 프로젝트 PDF는 전용 조회를 사용한다. 동일 렌더링에서 중복 조회를 줄이는 React `cache()`가 일부 조회에 적용되어 있다. Supabase 호출은 `no-store`다.
- 프로젝트·운영진·후기는 숫자 ID를 가진 원본 행과 별도 판본으로 저장한다. 기술·링크·이미지·운영진 상세 항목에는 관계형 테이블을 사용한다. 홈과 모집 설정에는 별도 관리 화면과 RPC가 있다. 공개 페이지와 수정 링크 미리보기는 공통 표시 컴포넌트를 사용한다.
- Supabase Auth 사용자와 활성 관리자 등록을 확인한 뒤 서버에서 `admissions` 또는 `content` 권한을 요청마다 검사한다. 관리 쓰기를 수행하는 RPC에서도 권한 및 예상 판본을 검사한다. 로그인 제한 상태는 DB에 저장한다. 공개 운영진 프로필의 소속·활동 정보는 관리자 권한에 영향을 주지 않는다.
- 신규 미디어 업로드는 [S3 설정](admissions-cms-preview.md#aws-미디어-전송)을 따른다. AWS 접근은 서버의 Vercel OIDC 및 IAM 역할을 사용한다. 브라우저에서 WebP 변환을 하고 만료되는 서명 URL로 초안 파일을 업로드한다. 서버는 실제 파일 길이·형식과 체크섬을 확인한다. 게시 후 S3 파일은 `assets.dnd.ac`에서 제공하며 기존 Supabase 미디어 참조에는 호환 경로가 있다.

## 수정 링크와 게시

1. 콘텐츠 담당자가 운영진 또는 조·조원에 연결되는 만료 링크를 발급한다. 링크의 토큰은 URL 프래그먼트로 전달하며, 서버는 해시를 보관한다. 작성 시작 시 해당 링크 범위의 HttpOnly 세션 쿠키를 발급한다.
2. 작성자는 해당 대상을 편집하고 실시간 미리보기를 본다. 제출 화면에는 `noindex, nofollow`, `no-referrer`, `private, no-store`가 적용된다. 공개 여부를 제어하는 경계는 링크 토큰, 세션, 만료 및 회수 상태다.
3. 관리자에서 변경 내용을 검토하고 승인한다. 승인 API는 내용 지문과 함께 DB 게시 작업을 먼저 기록한 뒤, 작업 ID를 Vercel Queues의 `submission-publications` 토픽에 보낸다.
4. 큐 소비자는 작업을 점유하고 충돌을 다시 확인한다. 필요한 미디어 공개 복사본을 준비한 뒤 DB에서 판본을 게시한다. 동일 작업이 재전달될 수 있으므로 작업 ID, 점유 상태와 내용 지문으로 중복 및 동시 편집을 제어한다.
5. 관리자 화면에서 게시 상태를 조회하고 대기 중인 작업을 다시 전송할 수 있다. 토큰 인증이 필요한 별도 내부 워커 경로도 있다. 현재 저장소의 `vercel.json`에는 큐 트리거가 정의되어 있다.

## 합격 조회와 모집 시각

- Passboard의 현재 이벤트는 `GET /events/current`, 지원 결과는 `POST /event/{eventId}/applicant/status/check`를 사용한다. [개발·검증 절차](admissions-cms-preview.md)에 양쪽 프로젝트의 연결 방법이 있다.
- PostgreSQL의 절대 시각을 기준으로 공개 준비 여부와 `시작 시각 ≤ 현재 시각 < 종료 시각`을 확인한다. 종료 시각을 비우면 운영진이 공개를 닫을 수 있다. 이벤트 응답은 한국 시각의 `+09:00` 표기를 사용한다. 홈페이지의 지원 버튼과 Passboard 노출 설정은 모집 화면에서 제어한다.
- 지원자 식별 정보는 서버에서 AES-256-GCM으로 암호화한다. 조회용 HMAC에는 별도 서버 키를 사용한다. 키 본문은 환경 변수로 관리한다.

## 개선 우선순위

1. **게시 큐 복구 자동화.** DB에 작업을 기록한 뒤 큐 전송에 실패하면 DB에 대기 작업이 남을 수 있다. 현재 관리자 재전송 기능을 유지하고, 오래된 대기 작업을 회수할 주기 실행과 지표를 추가한다. 검증할 때는 작업 기록 직후 전송 실패, 브라우저 종료, 이중 전송을 각각 다룬다.
2. **목록·관련 콘텐츠 조회 범위 축소.** 프로젝트와 후기의 일부 필터는 전체 게시 데이터를 받은 다음 적용한다. 프로젝트 상세의 후기 조회와 관련 프로젝트 조회도 순차 실행된다. 프로젝트 카드 및 프로젝트별 후기 전용 조회로 좁히고, 독립 조회는 병렬화한다. 변경 전후 RPC 호출 수, 응답 바이트, TTFB, 게시 직후 반영을 비교한다.
3. **관리 화면 업무별 코드 분리.** 제출 화면의 승인, 조별 링크, 운영진 링크 구분을 데이터 로딩과 변경 로직에도 적용한다. 모집·일반 콘텐츠는 목록 탐색 상태와 편집 상태를 분리한다. 권한 확인, 게시 충돌, 기존 초안, 만료 연장 계약을 회귀 기준으로 삼는다.

## 의존성 보안 확인

잠금 파일이 있는 레포 루트에서 전체, 운영 의존성, 개발 의존성을 각각 확인한다.

```sh
pnpm audit
pnpm audit --prod
pnpm audit --dev
```

[Dependabot 경보](https://github.com/DNDACADEMY/dnd-academy-v2/security/dependabot)와 함께 확인하고, 브랜치 결과를 운영 영향으로 해석하기 전에 배포 커밋과 잠금 파일을 비교한다. 런타임 경보는 의존성 경로, 해당 함수의 호출부, 외부 입력이 닿는 경로와 수정 버전을 대조한다. 의존성 변경 후에는 frozen 설치, 타입 검사, 테스트, Turbopack 빌드와 관련 기능의 프리뷰 동작을 확인한다.

### 2026-11-27 기준 확인

운영 배포 커밋 `725fc9f`와 `develop`의 소스 트리가 일치했다. 패치 전 전체 및 운영 감사에서 중간 등급 경보 1건이 나왔고 개발 의존성 감사에서는 경보가 없었다.

- `web → @vercel/queue@0.11.0 → minimatch@10.2.6`에서 DoS 경보가 확인됐다. 첫 수정 버전은 `11.0.1`이다. [GitHub 권고](https://github.com/advisories/GHSA-g3hv-75wg-m249) · [Dependabot #597](https://github.com/DNDACADEMY/dnd-academy-v2/security/dependabot/597)
- 현재 큐 SDK의 호출은 로컬 개발용 함수 경로 매칭에서 저장소의 `vercel.json` 패턴을 사용하고 최적화 옵션을 전달하지 않는다. 권고 조건은 외부에서 제어할 수 있는 패턴과 `optimizationLevel >= 2`다. 코드 추적에서 이 조건을 만족하는 운영 요청 경로는 확인되지 않았다.
- Queue SDK가 요청하는 minimatch 범위는 `^10.2.4`다. `@vercel/queue@0.11.0`에만 `11.0.1`을 적용한 뒤 전체 및 운영 감사에서 경보 0건을 확인했다. 수정 버전을 기본 지원하는 SDK로 업데이트할 때 override 제거 여부와 큐 발행·소비·재시도를 확인한다.
