# 홈 CMS 이관

2026-11-26에 공개된 [dnd.ac 홈](https://dnd.ac/)을 기준으로 FAQ 15개, 후원사 11개, 슬라이더에 노출되던 프로젝트 20개를 대조했다. FAQ는 공개 홈이 브라우저에 전달한 질문·답변에서 추출했다. 후원사의 링크·로고, 슬라이더의 프로젝트 및 순서, 누적 실적은 저장소의 같은 데이터와 대조했다. 누적 실적은 지원자 7,121명, 참가자 798명, 프로젝트 113개, 15기 이탈자 2명이다. 집계 기준일이 표시되지 않아 빈 값으로 옮겼다.

1. 스키마를 적용하고 기존 프로젝트 데이터를 먼저 이관한다. 홈 슬라이더는 프로젝트 ID에 외래 키로 연결된다. 신규 DB에서 기존 프로젝트가 준비되면 홈 시드를 적용한다.
2. `python3 scripts/import-home-cms.py`로 공개 원본을 읽기 전용으로 대조한다. `--html`에 캡처한 응답을 주면 같은 원본으로 다시 검증할 수 있다. `--sql` 출력은 검토 후 사용하는 시드이며 승인한 스냅샷은 `supabase/seeds/home-cms.sql`에 있다. 시드는 홈 초안이나 게시본이 이미 있으면 그대로 유지한다.
3. `node scripts/import-home-logos.mjs`로 기존 PNG와 공개 PNG의 바이트, 무손실 WebP의 크기·투명도·보이는 픽셀을 대조한다. `--sql` 모드에서는 대상 Supabase URL과 Storage 쓰기 권한을 환경 변수로 제공한다. 스크립트가 공개 저장소에서 다시 읽어 바이트를 확인한 경우에만 연결 SQL을 출력한다. 이 SQL을 적용하면 원본과 WebP의 해시가 각각 기록되고, 같은 로고 경로를 참조하는 행은 검증된 파일로 연결된다.
4. `public.published_home()`과 공개 홈에서 FAQ 순서, 후원사 링크·로고, 통계값을 대조한다. 슬라이더는 초기 자동 노출 모드에서 기존 최신 기수순 규칙을 따르며, 최초 표시된 20개는 운영진이 직접 노출을 지정할 때 시작 목록으로 쓸 수 있다.
5. 관리자 **홈 관리**에서 네 섹션을 편집하고 **초안 저장**, **저장한 초안 미리보기**, **홈 게시** 순서로 확인한다.

운영 데이터 이관은 승인된 배포 환경에 별도로 적용한다.

## 게시 실패와 미디어 정리

게시 시 새 공개 복사본은 게시 시도별 객체 키를 사용한다. 복사 실패나 DB 저장 실패 후에는 먼저 DB 참조를 확인하고, 사용되지 않는 복사본만 삭제한다. DB가 커밋됐지만 요청이 응답을 받지 못한 경우에도 판본이 참조하는 파일은 유지된다. 정리가 일시 실패하거나 프로세스가 강제 종료되면 정리 행이 남고, 만료된 정리 행은 다음 게시 요청에서 다시 처리한다. Supabase의 공개 복사와 DB 쓰기 사이에는 별도의 트랜잭션 경계가 있으므로, 원자적인 파일 공개가 필요하면 커밋된 참조를 통해서만 접근하는 별도의 서빙 구조가 필요하다.
